# フェーズ遷移ルール

アイデアの 6 フェーズは一定のルールに従って前進・逆戻りします。このルールに反する遷移は行いません。

## 前進ルール

### 原則

前フェーズが完了していないうちに後続フェーズのエージェント・スキルを起動しません。

### 各フェーズの完了条件

| フェーズ | 完了条件 |
|---------|---------|
| Phase 1: ブレスト | `01-brainstorm.md` の必須節がすべて埋まり、未解決疑問点が列挙されていること |
| Phase 2: PoC 計画 | `02-poc-plan.md` に検証項目と Go/No-Go 基準が明記されていること |
| Phase 3: PoC 実施 | `03-poc/<item>/` 配下に各 PoC 結果が記録され、成功基準との照合が済んでいること |
| Phase 4: ビヘイビア定義 | `04-behavior/README.md` に索引・ID 規約・ステータスサマリーがあり、各項目ファイルに優先度・ステータス付きのビヘイビア（前提・操作・期待）が書かれていること |
| Phase 5: タスク分解 | `05-tasks.md` に依存関係・担当区分・推定工数・対象ビヘイビアが揃っていること |
| Phase 6: ロードマップ | `06-roadmap.md` にマイルストーンとタイムラインが書かれ、着手判定が記録されていること |

### レガシー形式（`04-requirements.md`）

**形式判定**: `ideas/<name>/04-behavior/` ディレクトリが存在すれば新形式（ビヘイビア定義）、存在せず `04-requirements.md` があればレガシー形式（要件定義）として扱います。両方存在する場合は新形式を正とし、不整合として報告します。

レガシー形式のアイデアには従来の完了条件を適用します。テンプレートは `_templates/legacy/`（`04-requirements.md` / `05-tasks.md`）を正とします。

| フェーズ | 完了条件（レガシー） |
|---------|---------|
| Phase 4: 要件定義 | `04-requirements.md` に MoSCoW 優先度付きの要件（`REQ-N`）と受け入れ基準が書かれていること |
| Phase 5: タスク分解 | `05-tasks.md` に依存関係・担当区分・推定工数が揃っていること（`TASK-<要件番号>.<連番>`） |

### 判定ゲート

以下のゲートでは次フェーズへ進む前にユーザー判断を記録します。

- Phase 1 → 2: **追求判定**（このアイデアに PoC の価値があるか）
- Phase 3 → 4: **Go/No-Go 判定**（PoC 結果を踏まえて進めるか） ← 最重要
- Phase 4 → 5: **スコープ確認**（ビヘイビアの範囲は妥当か）
- Phase 6 完了: **着手判定**（実装を開始するか）

判定結果は該当フェーズのドキュメント末尾「判定」節に `結果 / 理由 / 日付` で記録します。スコープ確認は `04-behavior/README.md` 末尾（レガシー形式では `04-requirements.md` 末尾）に記録します。

## 逆戻りルール

### 逆戻りが妥当なケース

| 状況 | 戻り先 |
|------|--------|
| PoC 失敗・想定外の制約発見 | Phase 1 |
| ビヘイビア定義中に PoC 不足を発見 | Phase 2 または 3 |
| タスク分解で複雑すぎると判明 | Phase 4 |
| ロードマップが非現実的 | Phase 4 または 5 |

### 逆戻り時の手順

1. 該当アイデアの `README.md` のステータスを「🔁 再検討中」に更新します（戻り先のフェーズ行）。
2. 戻り先より後のフェーズは「⬜ 未着手」または「🔁 再検討中」に戻します（内容は残して参照可能に）。
3. 「判定」節に逆戻りの理由と日付を追記します。
4. 改めて戻り先フェーズから進めます。

## 中止・保留

- **中止**: README.md ステータスを「❌ 中止」に変更し、`01-brainstorm.md` に要因を追記します。
- **保留**: README.md を「⏸️ 保留」に変更し、再開条件を `01-brainstorm.md` に明記します。

## スキル・エージェントとの対応

- `/advance-phase` は前フェーズの完了条件と判定ゲートを自動確認します。完了条件を満たさない場合は前進を拒否します。
- エージェント（`brainstorm`, `poc-planner`, `behavior`, `task-decomposer`, `roadmap`）は対応するフェーズでのみ起動します。
- `/generate-spec` は Phase 4 完了後（新形式のみ）、`04-behavior/` から `spec.md` を自動生成します。
